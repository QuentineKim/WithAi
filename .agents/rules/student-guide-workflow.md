# 기말과제 바이브 코딩 워크플로 규칙 (`docs/ai/prompt-engineering-guide-student.md` 준수)

이 저장소에서 기말과제(`2023391007_김관현_기말/` 등 MVC Lua/LÖVE 프로젝트)를 작업할 때 아래 절차를 항상 따른다.

1. **참고 문서**: 작업 시 `docs/ai/prompt-engineering-guide-student.md`의 6요소, 세션 운영, 테스트 먼저, 로그 양식을 기준으로 삼는다.
2. **1 세션 = 1 태스크 = 커밋 1개**: 한 번에 하나의 목표만 다룬다. 커밋되지 않은 이전 태스크가 남아 있으면 새 기능 시작 전에 먼저 정리·커밋 여부를 확인한다.
3. **계획 먼저 및 승인 대기**: 코드를 수정·생성하기 전에 한 문장 목표, 수정 허용 파일, 읽기 전용 파일, 먼저 쓸 테스트 목록, 위험 요소, 질문을 먼저 제시하고 사용자 승인을 기다린다.
4. **테스트 먼저(TDD)**: 기능 구현 전 `tests/`(`helper.lua` 규약: 통과 시 명시적으로 `true` 반환)에 테스트를 먼저 작성해 실패를 확인한 뒤 구현한다.
5. **언어·MVC 경계 준수**: Lua 5.1/LuaJIT 문법만 사용하고(`//`, `!=`, `table.unpack`, `goto`, `<const>`, 전역 `utf8` 금지), 모든 변수/함수는 `local`만 사용하며(`SETGLOBAL` 0건), `layer_check.lua` 계층 경계를 지킨다.
6. **검증·리뷰·로그**: 구현 후 `test-runner`와 `lua-reviewer`로 검증·리뷰를 수행하고, `worklogs/`에는 `worklog-writer` 양식으로 사용자 프롬프트 원문 그대로, 실제 실패·수정 이력(Before→After), 인계 메모를 남긴다(직접 확인하지 않은 실행은 `(확인 필요)` 표기, 학번·개인정보 제외).
