# 모놀리식 고통 기록 (monolith_pain)

> 2주차 산출물. 모놀리식 겔러그(`my_galaga/main.lua`)를 만들고 요란한 보스 탄막을 추가하며 겪은 고통을 **숫자와 함께** 남긴다.
> 이 기록은 4주차에서 MVC 구조와 **정량 비교**하는 기준선이 된다.

---

## 1. 기본 정보
- **작성자:** 실습 학생 (AI 협업)
- **전체 코드 줄 수(`main.lua`):** 725줄 (기본 모놀리식 약 448줄 → 요란한 보스 탄막 추가 후 725줄, **+277줄 순증가**)
- **파일 개수:** 1개 (`my_galaga/main.lua` 단일 모놀리식 파일, 설정용 `conf.lua` 제외)

## 2. Model-View 결합 지점 (로직 속 연출/사운드 호출)
로직 함수 안에서 `love.graphics`/파티클/사운드/화면흔들림을 직접 건드린 대표적 위치 5곳:

| # | 위치(함수/블록) | 섞인 연출 | 분리한다면 어디로? |
|---|----------------|----------|-------------------|
| 1 | 충돌 판정 (`내 총알 × 적`) | `explode(e.x, e.y, 18)` 파티클 폭발 + `flash = 0.05` 직접 대입 | Model은 사망 이벤트(`EnemyKilledEvent`)만 발행, 연출은 View(`ParticleView`)가 담당 |
| 2 | 충돌 판정 (`적 총알 × 플레이어`) | 라이프 감소 직후 `screenShake = 0.4` + `flash = 0.15` + 파티클 강제 호출 | Model은 `PlayerDamagedEvent`만 발행, 연출은 View의 `Camera`/`FXManager`로 분리 |
| 3 | 보스 출현 트리거 (`spawnBoss`) | `bossWarningTimer = 2.4` + `screenShake = 0.5`로 지진 및 사이렌 직접 조작 | `GameStateModel`(Phase 전환)과 View의 `WarningCutscene`으로 분리 |
| 4 | 보스 피격 루프 (`내 총알 × 보스`) | `boss.hp` 감소 직후 `boss.hitFlash = 0.08` + `screenShake = 0.05` + 스파크 파티클 | Model은 HP 감쇠만 처리, View의 `BossRenderer`가 피격 플래시 표현 |
| 5 | 보스 격파 시 (`bossDefeatedTimer`) | 로직 루프 한복판에서 2초간 매 프레임 `explode()` + `screenShake`를 무작위 발생 후 `won = true` 조작 | Model의 상태 전이(`Phase.WON`)와 View의 시퀀스 연출로 완전 분리 |

## 3. 테스트 가능성
- **`love` 없이 로직만 require 가능한가? (예/아니오):** 아니오
- **"총알 1,000개 × 적 충돌 시 점수 계산"을 창 없이 검증할 수 있는가? (예/아니오):** 아니오
- **불가능하다면 그 이유를 한 줄로:**
  - 파일 최상단부터 `love.graphics`, `love.keyboard` 등 LÖVE2D 전역 런타임에 직접 결합되어 있고, 로직 함수들이 독립된 모듈로 `return`되지 않고 `love.update()` 내부에 하드코딩되어 있어 순수 `lua`나 `luajit` CLI에서 로드 즉시 전역 미정의 크래시가 발생함.

## 4. 기능 추가 전파 기록
추가한 기능: ( ) 유도 미사일  ( V ) **보스 탄막**  ( ) 기타: 요란한 대형 네온 보스 & 3대 탄막 & 연쇄 대폭발

| 수정한 함수/블록 | 수정 이유 | 부작용(깨진 것) |
|------------------|----------|----------------|
| **1. 최상단 전역 상태 영역** | 보스 엔티티, 스폰 여부, 경고 타이머, 연쇄 폭발 큐 전역 변수 선언 | 상태가 파일 전역에 흩어져 어디서 누가 값을 변경하는지 추적 불가 |
| **2. 매직 넘버 상수 영역** | `BOSS_SPAWN_SCORE`, `BOSS_MAX_HP`, `BOSS_BULLET_SPEED` 추가 | 게임 밸런스 파라미터가 파일 상단에 박혀 외부 주입이나 데이터 테이블화 불가 |
| **3. `resetGame()` 함수** | 게임 재시작 시 보스 상태, 타이머, 탄막 잔여 큐 초기화 | 신규 엔티티가 추가될 때마다 리셋 로직을 매번 찾아다니며 수동 추가해야 함 |
| **4. `love.update()` - 연출 타이머** | 보스 사이렌, 피격 화이트 플래시, 2초 연쇄 폭발 카운트다운 삽입 | 물리/게임 로직 루프 내부에 화면 연출용 타이머 감쇠가 침투해 로직 가독성 훼손 |
| **5. 적 총알 자료구조 & 이동 루프** | 보스의 다방향 각도 탄막(방사/회오리)을 위해 총알에 `vx, vy, color` 추가 | **보스와 전혀 상관없는 일반 적 총알 생성부와 이동 코드까지 전부 수정되어** 기존 하향 탄환이 멈추거나 튕기는 결함 유발 |
| **6. 보스 이동 및 3단 탄막 패턴** | 보스 호버링/좌우 이동, 360도 원형 방사, 7방향 부채꼴 조준탄, 나선 회오리탄 알고리즘 추가 | `love.update()` 한복판에 100줄 이상의 탄막 분기가 끼어들며 단일 함수가 300줄 이상으로 비대화 |
| **7. 충돌 판정 루프** | 내 총알 × 보스 피격 및 데미지, 보스 탄환 × 플레이어 충돌 판정 신설 | 중첩 충돌 루프가 복잡해지며 보스가 이미 파괴되어 연쇄 폭발 중인데도 플레이어가 계속 보스에게 충돌하는 판정 버그 발생 |
| **8. `love.draw()` 렌더링 루프** | 대형 보스 본체, 에너지 코어, 보스 전용 HP 게이지 바, 사이렌 점멸 경고 텍스트 추가 | 화면 그리기 함수가 200줄 넘게 팽창하고 상태(`bossDefeatedTimer`)에 따라 그리기 분기가 복잡하게 얽힘 |
| **9. 게임 승리/재시작 UI** | 보스 격파 시 최종 승리(VICTORY) 오버레이 및 점수 HUD 출력 분기 추가 | 게임 오버 화면과 승리 화면의 UI 코드가 중복 생성되어 UI 스타일 일관성 깨짐 |

- **총 전파 위치 수:** **9곳** (상태 정의 → 상수 → 리셋 → 연출 타이머 → 적 총알 구조 → 탄막 로직 → 충돌 판정 → 보스 렌더링 → 승리 UI)
- **디버깅 체감 난이도(1~5):** **4** (보스 탄막 속도를 일반 총알과 통일시키려다 기존 적 탄막 이동이 깨지고, 사망 연쇄 폭발 중 추가 피격이 일어나는 전파 버그 디버깅에 큰 시간 소모)

## 5. AI 바이브 코딩 오염
- **AI가 엉뚱한 변수를 건드린 사례:**
  - "보스 탄막을 추가해줘"라고 요청했을 때, AI가 일반 적 총알 리스트(`enemyBullets`)와 플레이어 총알 리스트(`bullets`)를 혼동하여 플레이어 발사체에 보스의 회오리 탄막 각도 계산 로직을 주입해 플레이어가 보스 탄환을 발사하는 버그 발생.
- **이미 있는 로직을 중복 생성한 사례:**
  - 이미 상단에 AABB 충돌 판정 함수 `overlaps(a, b)`가 구현되어 있었으나, AI가 이를 인지하지 못하고 보스 충돌 판정용 `checkBossHit(bullet, boss)` 함수를 별도로 중복 생성하여 충돌 판정 공식이 두 갈래로 나뉨.
- **파일이 길어질 때 프롬프트 정확도가 떨어진 지점:**
  - 파일 길이가 500줄을 넘어가자 `love.update()` 함수의 블록 닫기(`end`) 짝이 어긋나 문법 에러(Syntax Error: 'end' expected)가 반복 발생했고, `screenShake` 감쇠 코드가 루프 내에 중복 삽입되어 화면 진동이 비정상적으로 빠르게 꺼지는 현상이 발생함.

## 6. 다음 주(MVC) 가설
- **무엇을 Model로 빼면 테스트가 가능해질까?**
  - `PlayerModel`, `EnemyFormationModel`, `BulletModel`, `BossModel`을 LÖVE 라이브러리 의존성이 전혀 없는 **순수 Lua 테이블 및 메타테이블 OOP**로 분리한다.
  - 이렇게 하면 LÖVE 창을 띄우지 않고도 `luajit` 명령 한 줄로 "보스에게 총알 90발이 적중했을 때 정확히 체력이 0이 되고 사망 상태로 전이되는가"를 0.05초 만에 헤드리스 단위 테스트로 검증할 수 있다.
- **무엇을 View로 빼면 연출 수정이 로직에 영향을 안 줄까?**
  - `ParticleView`, `CameraEffect(Shake/Flash)`, `BossView`, `HUDView`를 별도 모듈로 분리한다.
  - Model은 "보스가 피격되었다", "보스가 파괴되었다"는 **상태 변경/이벤트만 발생**시키고, View가 이를 감지하여 폭발 파티클과 화면 흔들림을 그리도록 만들면 연출 수치가 바뀌어도 게임 규칙(HP, 충돌)에 절대 영향을 주지 않는다.
- **Controller로 분리할 입력 처리는 무엇인가?**
  - `love.keyboard.isDown` 및 `keypressed`를 `PlayerController` / `InputManager`로 격리한다.
  - 물리/업데이트 루프에서 직접 키 입력을 검사하지 않고, 입력을 추상화된 커맨드(`moveLeft`, `moveRight`, `shoot`)로 해석하여 Model에 전달하면 키 리바인딩이나 자동 재생(Bot) 테스트가 극도로 쉬워진다.
